# Repo Bridge

## Canonical Homes

| Home | Path | Owns |
| --- | --- | --- |
| Product repo | `../sentinel-virus-scanner/` | Artifact-scanner product continuation, roadmap, Rust scanner evolution, product docs |
| Course repo | `../nycu_114-2_network_security_practices/projects/project-i-virus-scanner/` | Submitted course artifact, official brief, report, grading evidence |
| Planning repo | `../planning-everything-track/` | Capacity, schedule, lightweight locators, next actions |

## Boundary

The product repo may reuse original code and safe fixtures from the course
project. It should not carry course-only artifacts such as official PDFs, LMS
submission state, grading status, or submission-named report PDFs.

The course repo may link to this product repo as the continuation path, but it
should not become the product workspace.

The planning repo should keep only status and routing:

- where the product repo lives
- why it exists
- current next action
- whether it fits the current week
- what should remain frozen in the course archive

## Current Bridge Decision

On `2026-04-29`, the product continuation was split into
`../sentinel-virus-scanner/` using the `sentinel-` family prefix. The course
project remains frozen as the submitted Network Security Project I archive.
